# Project Documentation

## 1. Project Overview

The Learning Recommender System is a machine-learning project that ranks next-course recommendations from learner profile data. The dashboard accepts an existing learner ID or a manually entered profile, compares the profile with similar learners, and presents course recommendations with match scores and supporting reasons.

The current project uses `data/learning_path_dataset.csv` as its source. It is not built on OULAD. The source contains course codes and learner attributes, but no learning-material IDs, activity types, resource descriptions, or resource links. Therefore, the system recommends courses rather than individual learning materials.

## 2. Dashboard Workflow

The Streamlit page presents five numbered sections in this order:

1. **Student Input:** Choose an existing learner ID to load its profile, or keep the manual-entry option. Inputs include current course, learning level, learning preference, completed courses, study hours, performance score, and the number of recommendations (3–10).
2. **Loading and Processing:** Shows dataset status, record and course counts, the number of excluded target rows, feature-processing information, and a sample of the data.
3. **EDA Graphs:** Displays score distribution, learning-preference counts, study hours versus performance, and recorded next-course label counts.
4. **Recommendation Output:** Displays ranked course codes and match scores. It includes a match-score chart and a chart comparing the learner's score and study hours with the nearest learners.
5. **Recommended Resources:** Explains that the CSV has course codes only and lists the recommended course codes when results are available.

A sticky navigation bar links to each section. Input validation messages appear in the Student Input section.

## 3. Dataset

### Required Columns

| Column | Type or format | Use |
| --- | --- | --- |
| `Learner_ID` | Unique identifier | Existing-learner lookup and optional self-match exclusion |
| `Current_Course` | Course code | Profile feature and recommendation exclusion |
| `Completed_Courses` | Comma-separated course codes | Course-history features and recommendation exclusion |
| `Learning_Level` | Category | Profile feature |
| `Learning_Preference` | Category | Profile feature |
| `Time_Spent_Hours` | Numeric, 0–100 | Scaled profile feature and profile comparison |
| `Performance_Score` | Numeric, 0–100 | Scaled profile feature and profile comparison |
| `Next_Course_Recommendation` | Course code | Supervision target recorded in the dataset |

The values accepted for categorical fields are obtained from the loaded dataset rather than being hard-coded as OULAD categories.

### Data Validation and Preparation

`src/data_loader.py` reads the CSV, checks for required columns, strips surrounding whitespace from string fields, converts the two numeric fields, and rejects missing values, blank required strings, duplicate learner IDs, and out-of-range hours or scores. Completed course codes are parsed from comma-separated strings into a normalized list.

Before model training, `filter_trainable_rows` excludes records whose recorded recommendation is the learner's current course or is already in their completed-course list. The saved metrics currently report 286 excluded records and 714 rows retained from the 1,000-row dataset.

## 4. Features and Recommendation Method

`src/features.py` builds the same feature representation for training and live profiles:

- Current course, learning level, and learning preference are categorical indicators.
- Each completed course becomes a binary history indicator.
- Study hours and performance score are divided by 100 to scale them to 0–1.

`src/recommender.py` vectorizes these dictionaries with scikit-learn's `DictVectorizer` and fits a brute-force nearest-neighbor index using cosine distance. The default neighborhood is 20 learners. For an existing learner lookup, that learner's own ID is excluded from the neighbor results.

Recommendations are generated by accumulating similarity-weighted votes for neighbors' recorded next-course labels. The current course and completed courses are removed from the candidate list. Results are ordered by vote weight and include:

- **Rank:** position in the returned list.
- **Course:** recommended course code.
- **Match Score:** the course's accumulated neighbor vote divided by the total similarity weight of the selected neighbors.
- **Why Recommended:** number of similar learners who selected the course and their average performance score.

The number of returned recommendations can be selected from 3 to 10. When training the model, evaluation uses five recommendations for the hit-rate metrics.

## 5. Training and Evaluation

From the project root, run:

```bash
python train_model.py
```

Training uses a stratified 80/20 split of eligible rows with random state 42. It evaluates recommendations on the holdout set, calculates ranking metrics and a popularity baseline, then fits the saved recommendation bundle on all eligible rows. The script writes:

- `models/recommender_model.joblib` — vectorizer, nearest-neighbor index, training profiles, targets, and learner IDs.
- `models/metrics.json` — dataset counts, split information, model metrics, and baseline metrics.

### Current Saved Results

| Metric | Model | Majority/popularity baseline |
| --- | ---: | ---: |
| Top-1 accuracy | 11.19% | 10.49% |
| Hit rate at 3 | 33.57% | Not calculated |
| Hit rate at 5 | 53.15% | 45.45% |
| Mean reciprocal rank at 5 | 0.2472 | Not calculated |

The holdout contains 143 evaluated learners. The current top-five hit rate is about 7.7 percentage points above the baseline. This is a modest improvement on this dataset; it should not be presented as evidence of broad real-world effectiveness. The values above describe the current `models/metrics.json` and may change after retraining.

## 6. Run the Dashboard

Install dependencies, train the model, and start Streamlit:

```bash
python -m pip install -r requirements.txt
python train_model.py
streamlit run app.py
```

The application expects the CSV at `data/learning_path_dataset.csv` and the trained model at `models/recommender_model.joblib`. If the dataset changes, retrain the model so its saved profile features and targets match the source data.

For Windows PowerShell, create and activate a virtual environment first:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

For macOS or Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

## 8. Limitations and Responsible Interpretation

- Recommendations are course codes, not links to courses, quizzes, videos, or other learning materials.
- The target is the dataset's recorded `Next_Course_Recommendation`; the project does not establish that a course caused better outcomes.
- Recommendations depend on patterns in this one dataset and may not generalize to other learners or institutions.
- More than one quarter of source rows are excluded because their target conflicts with the learner's current/completed course history. Review this rule if the source dataset's target semantics change.
- Holdout metrics are modest. Retrain and re-evaluate after any dataset or feature change, and report the current metrics rather than assuming improvement.
